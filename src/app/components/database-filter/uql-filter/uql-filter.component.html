Placement
Scopes and matching semantics

Global totals, exact slots, and entity scope.

No scope
Uses the field's global meaning: usually a lineage total or any relevant slot.
Main / Parent / Main parent
Main-parent slot only.
GP1 / Left / Great parent 1
Left great-parent slot only.
GP2 / Right / Great parent 2
Right great-parent slot only.
GP / Any GP / Great parent
Either great parent may satisfy the predicate; it does not require both.
Characters in (...)
Any Main, GP1, or GP2 character matches a listed value.
Characters not in (...)
All three character slots must be outside the list.

Examples: Speed >= 6 is a lineage total, Main Speed >= 3 is one slot, and GP Speed >= 3 accepts either great parent.

Expression grammar
Operators and expressions

Numeric, text, collection, and boolean syntax.

= == != <> > >= < <=
Numeric or exact-value comparisons. = and == are equivalent, as are != and <>.
between A and B
Inclusive numeric range.
+ - * /
Numeric arithmetic; division uses integer semantics.
% / mod
Modulo remainder, for example Wins % 2 = 0.
in (...) / not in (...)
Include or exclude listed values. On collections, in behaves like has any.
has / contains
Require one collection value. The names are aliases.
has any / contains any
Require at least one listed collection value.
has all / contains all
Require every listed collection value.
does not have
Exclude one collection value.
like / ilike / not ilike
Text patterns; ilike is case-insensitive and % is a wildcard.
and / or / not
Boolean composition and negation.
( ... )
Explicit grouping. Use parentheses whenever and and or are mixed.

Advanced
White-skill ranking and raw functions

Choose preferred skills, then optionally fine-tune how matching rows are ordered.

For a normal search, use one of the four ranking functions below and leave every numeric setting at its default.

optional white in (...)
Require at least one listed skill somewhere in the combined lineage, then put rows with more and stronger matches first.
optional main white in (...)
Require at least one listed skill on the main parent, then rank the matching rows.
optional any white in (...)
Require at least one listed skill in either the combined lineage or the main-parent factors, then score matches from both.
lineage white in (...)
Do not exclude any rows. Prefer lineages that repeat the listed skills across Main, GP1, and GP2.

How to add parameters

Keep the skills first. After the final skill, add a comma and write parameter_name = number before the closing parenthesis. Add more parameters the same way, separated by commas.

priority and weight work on every ranking function. Use optional-white weights only with an optional ... white function, and lineage weights only with lineage white.

These examples are clickable. The first changes optional-white scoring; the second changes lineage scoring.

Priority groups decide which preference matters first.

priority = 0
The primary preference. Its score is compared before every higher-numbered group.
priority = 1, 2, ...
Fallback preferences. Group 1 is checked only when two rows have the same group-0 score; group 2 only breaks a further tie.
priority_group / prio_group / group
Compatibility aliases for priority. Prefer priority = N in new queries.

Example: put your most important ranking goal in priority = 0 and a secondary goal in priority = 1. A very strong group-1 match can never outrank a better group-0 match.

Optional-white weights change the default score: 100 × different skills found + matching stars.

type_weight
Points for each different requested skill found. Default: 100. Raise it to favor variety over star level.
level_weight
Points for each star on matching factors. Default: 1. Raise it to favor higher-star copies.
match_weight
Extra points for every matching factor entry, including repeated copies of the same skill. Default: 0.
proc_weight
Extra points based on each match's estimated inheritance chance. Default: 0 (disabled).
proc_kind
Chance table used by proc_weight: 2 for race, 3 for skill (default), or 4 for scenario factors.
affinity
Replace the affinity calculated for each result with one fixed value when estimating inheritance chance. Normally leave this unset.

Lineage weights control how lineage white rewards repeated skills.

stack_weight
Starting size of each matched skill's stack score. Default: 1000.
base
Growth for repeated copies of a skill. Default: 110, meaning each copy multiplies that stack component by 1.10.
decay
How much the next-best requested skill contributes. Default: 50: best skill gets full stack value, second gets half, third gets one quarter.
occurrence_weight
Flat extra points for every matching copy, separate from the stack calculation. Default: 0.
weight
Multiply the final score from this ranking function. Default: 1. It works with both optional-white and lineage scoring.

Raw helpers are the backend forms used by the readable syntax.

support_card / has_support_card
Raw support-card functions. Accepted keys: id, card_id, support_card_id, lb, limitbreak, limit_break, limit_break_count, exp, and experience.
contains / has / any / overlaps / has_all / contains_all / all
Accepted backend-style collection functions. The readable operators above are preferred.

lightbulboptional white requires at least one listed match. lineage white only changes order. To require every listed skill, use a normal has all predicate.
